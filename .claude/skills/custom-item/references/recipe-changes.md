# 配方材料变更

多路径融合神器的成品属性通常是**固定值**，与走哪条路径无关（`item_fusion_agile` 是无属性纯令牌，只作合成条件）。新增或替换可选材料时，按材料投入成本用 `AskUserQuestion` 给 2–3 档让用户取舍，每档标明舍弃了哪些机制：

- 廉价/限购令牌材料：不贡献属性，维持现状
- 高价值神器材料（数千至数万金）：可追加一两条简单数值（伤害/护甲/生命回复）；触发型机制（换血、连锁效果、主动单体增益）通常不带入，避免成品堆叠过多机制

可选材料的**主动技能**要继承到成品时，三处同步：

1. KV：成品 `AbilityBehavior` 改为目标型，补齐 `AbilityUnitTarget*` / `AbilityCastRange` 与原有的充能 / 共享冷却
2. 脚本：把源材料的 `OnSpellStart` 搬进成品实现，充能消耗判定改查成品自己的物品名
3. bot：除 `bot-item-usage` 的 ItemSpec 外，检查按物品名硬编码调用的文件，显式加上新物品
