# Dota Patch Sync

Dota 2 官方发新版后，本图要核对并同步的改动很多，按类别拆成几块，各块分批做、分批合并。本 skill 是总入口：先定范围和优先级，再把每块交给对应的 skill 或细则。

`<版本>` 目录按 `docs/reference/` 实际存在的取（含 `7.41f` 这类字母后缀），上一版指排在新版之前的那个目录。

## 整体流程

```
取资料 → 判断冲击面 → 建主 issue 与子 issue → 紧急修复先发 → 各块分批同步 → 确认类 issue 逐条核对 → 发版
```

1. **取资料**：下载中英文更新日志，解包新版参考快照到 `docs/reference/<版本>/`，细则读 `references/patch-sources.md`
2. **判断冲击面**：对比上一版与新版快照，先找「会让本图直接坏掉」的改动，细则读 `references/impact-triage.md`。官方更新后玩家反馈的「买不了、合不出、选不了」多半出在这里
3. **建主 issue 与子 issue**：结构、顺序、勾选规则读 `references/issue-structure.md`
4. **紧急修复先做**：直接会坏的单独一个 PR，先于其余同步合并发版，不等全部同步完
5. **各块分批同步**：见下面各章节，每块独立分支、独立 PR。合并功能 PR 前后按根 `CLAUDE.md`「Git」走一遍 release PR 的更新日志与 Checklist
6. **确认类 issue 逐条核对**：每个更新日志章节一个确认 issue，核对完才关
7. **发版**：release PR 始终由维护者审批，发版步骤见 `deploy`

## 子任务分块与交给谁

| 块 | 内容 | 交给 |
|---|---|---|
| 紧急修复 | 被官方移除的物品或技能，引用它们的配方、商店、电脑出装、抽奖池，配置格式变化导致功能失效 | `references/impact-triage.md` 定范围，物品改动走 `update-items-override`，实机验证走 `dota-live-test` |
| 综合改动 | 更新日志「综合改动」：金钱经验、小兵、防御塔、符文、肉山等机制 | 下面「确认类 issue」一节 |
| 地图地形 | 更新日志「地图改动」：塔位、营地、地形文件 | `dota-map-update`，单独子 issue。更新地形文件会自动带来营地与野区变化，营地类条目不再单列。地形动了以后，脚本里写死的坐标（电脑 AI 的塔位、营地、路径点等）要另行核对，用 `dota-map-update` 验证时导出的实体坐标做依据。电脑眼位要按新地图重新规划，另开「电脑眼位更新」子 issue，不并进地形 PR |
| 中立生物 | 更新日志「中立生物更新」：营地、赏金、野怪数值 | `references/items-and-neutral.md` 的「中立生物」一节 |
| 物品 | 更新日志「物品改动」：基础物品、上位物品、配方、价格 | `update-items-override`，范围与批次读 `references/items-and-neutral.md` |
| 中立物品 | 更新日志「中立物品改动」：掉落表、等级、附魔 | `references/items-and-neutral.md` 的「中立物品」一节，不是每版都有改动 |
| 英雄 | 更新日志「英雄改动」：技能与天赋 | 下面「英雄改动」一节 |
| 克隆技能与物品 | 所有 `BaseClass` 指向原版的克隆：抽奖、塔技能（`npc_abilities_custom*.txt`），升级装备、神器（`npc_items_clone.txt` / `npc_items_custom.txt` / `npc_items_artifact.txt`） | 下面「克隆技能与物品」一节 |

物品、中立、英雄、克隆四块互相独立，可以并行。紧急修复必须先合并，其余块都建立在它之上。

## 英雄改动

对照新版更新日志「英雄改动」一节，核对每名英雄的技能与天赋改动是否影响本图的克隆、觉醒、自制、抽奖技能和电脑 AI 配置。完整做法读 `references/hero-changes.md`，要点：

1. 手工列英雄清单，写成主 issue 正文的勾选清单
2. 只读摸底，按「本图要不要动手、动手要不要判断」分 A / B / C，不按官方改动大小分
3. A 直接勾掉，B 按批自动同步，C 每名或每类拆子 issue、先定方向再改
4. 同步数值与 `Bot.Build` 走 `update-abilities-override`「补丁日志同步」和 `update-bot-hero-build`
5. 更新日志不在各 PR 里写，发版 PR 合成一条

## 克隆技能与物品

只同步覆盖文件不够：克隆块里写死的值不会跟着官方变，官方新增的 KV 标记（如 `IsBreakable`）克隆不继承，克隆把某键写成单值还会盖掉官方新加的子键（如 `apply_effectiveness`）。7.42 漏了这一步，事后补做（`windy10v10ai/game#2830`）。

1. 用脚本列出全部克隆，逐个对比上一版与新版参考里 `BaseClass` 原版块的差异
2. 克隆用到的键被删除或改名的优先处理，其次是克隆写死的键官方改了值、官方新增的标记与子键
3. 技能走 `clone-ability` 修正模式，物品走 `clone-item` 更新模式。能按规则算出唯一答案的直接改，设计取舍交维护者并附推荐


综合改动、中立生物、物品、中立物品、英雄各有一个确认 issue，保证更新日志每一条都被看过：

1. 对照更新日志对应章节，逐条列成勾选清单，已处理的写明由哪个 PR 完成
2. 标出影响本项目的部分：本图有覆盖、克隆、自制，或电脑 AI 配置了的
3. 需要改的拆工作项。不需要改的在行内划掉并写原因，例如「不需要，更新地形文件时会自动变化」「跟随官方，本图无覆盖」
4. 综合改动里的机制（金钱经验、小兵、肉山、符文等）先 grep 本图有没有自己的覆盖，没有就是跟随官方，不用改

清单随进度回填，不要等全部做完再写。

## 分工与档位

- 取资料、解包、对照快照、摸底分类、跑实机检查：最便宜档，把判定标准和要带回的数字写进提示
- 按已定方案批量改 KV、配方、配置：主力档
- 审查：主力档，只读
- 方向取舍（物品是否恢复、中立等级与时间表、哪个机制不跟官方）：留在主对话，由维护者拍板，不让子代理定

## 坑

- 数值以快照文件为准，不信更新日志的中文：日志可能有错翻或未翻译的条目
- 任何会让地图开不了局的改动先修：配置格式不兼容、引用了被删的物品名，详见 `references/impact-triage.md`
- 紧急修复不与批量同步混在一个 PR，保证能单独发版
