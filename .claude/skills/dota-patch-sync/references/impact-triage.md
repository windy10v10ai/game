# 冲击面判断：先找会直接坏的

官方更新后，先别逐条同步，先找「本图在新版里会直接坏掉」的改动。这些要先修、先发。派最便宜档并行做，主对话汇总。

## 要查的几类

每类的做法都是「对比上一版与新版快照，再 grep 本图引用」，结果写进一份本地汇总，每条带系统名、官方怎么改、本图哪里引用。

### 1. 被移除或改名的物品与技能

- 对比两版 `items.txt`、`npc_abilities.txt`，列出新版没有的、`IsObsolete`、`ItemPurchasable` 变成 0 的、改了名的
- 对每一项 grep 本图引用：商店 `game/scripts/shops.txt`、物品配方 `ItemRequirements`、电脑出装与卖物清单（`src/vscripts/ai/`）、抽奖池（`src/vscripts/modules/lottery/`）、中立掉落表、本地化
- 配方引用了被移除的材料，会让上位物品买不了、合不出，玩家最先反馈的就是这类
- 处理方向由维护者定：恢复该物品（在 override 里补回 `ItemPurchasable` 等键）、换材料、还是下架。别自行删除玩家会用的东西

### 2. 物品价格、配方变化带来的联动

- 材料改价会让依赖它的配方费失衡，规则见 `update-items-override`「配方价格联动」
- 配方变成免卷轴（`ItemCost` 为 0）的物品，是自动合成，没有配方卷轴。检查脚本若预期有卷轴会多报，不是游戏问题

### 3. 配置文件格式变化

- 对比 `neutral_items.txt` 等文件的结构，不只对比数值。7.42 把平铺的 `items` 改成 `item_pools` 里多个池，每池 `options` 个候选，本图旧格式不报错但中立物品选不出来
- 格式变化时先在 Dota Tools 实机确认功能是否还能用，再改文件。改文件时同步 TS 里对应的配置（电脑中立配置要与 `neutral_items.txt` 一致）

### 4. 本图自制逻辑依赖的原版行为

- 本图 TS / Lua 代码里引用的原版 modifier 名、物品名、技能名、事件名，被改名或语义变化时会静默失效
- 对改名的物品、技能，用旧名在 `src/` 与 `game/scripts/` 里 grep

## 产出

一份汇总，按严重度排序：

| 级别 | 含义 | 处理 |
|---|---|---|
| 阻断 | 开不了局、买不了、合不出、选不了 | 紧急修复子 issue，先发 |
| 数值失衡 | 配方总价、数值与设计不符 | 并入对应块 |
| 无影响 | 本图没引用 | 在确认类 issue 里划掉并写原因 |

写成主 issue 之外的一份本地文件（放 scratchpad），再据此建紧急修复子 issue。

## 紧急修复的验收

- 实机检查：`npm run dota:check` 的对应检查项，流程见 `dota-live-test`。验收内容包括合成链能合出、新装备数值与价格、日志无脚本错误
- `npm test`、`npm run build:vscripts`、本地化检查通过
- 检查脚本的结论会有误报，核对每条异常的原因后再判断，不要只看通过与否
