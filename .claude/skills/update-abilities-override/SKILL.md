# Update Abilities Override

维护 `game/scripts/npc/npc_abilities_override.txt`：仅写**与当前参考的差分**（扩展等级、有意加强等），引擎从原版合并缺失键。

## 前置条件

- 参考文件路径与英雄名 / 技能名查找见 `game/scripts/npc/CLAUDE.md`「原版 KV 参考」。`<版本>` 目录按 `docs/reference/` 实际存在的取（含 `7.41f` 这类字母后缀），上一版指排在新版之前的那个目录
- 用 `grep` / 片段读取定位，**禁止**一次读入整个 override 文件
- 判断技能实际生效的数值时，精确读 override 该技能整段（到下一个顶层技能名前），顶层字段和 `AbilityValues` 子块都看：override 常把数值写成子块（如 `AbilityManaCost { "value" "9 10 11 12 13" }`），只 grep 顶层会误判（例：`drow_ranger_frost_arrows` 原版 0 蓝，本图子块里是每箭 9–13 蓝）。override 未覆盖时才回落原版
- 两种用法：给出**补丁日志**（用户贴的逐条「旧值→新值」，或 `docs/reference/<新版>/patchnotes*.md` 里某批英雄的段落）走「补丁日志同步」，只给英雄或版本走「执行顺序（逐英雄）」全量重整

## 补丁日志同步

默认**自动完成**：规则能唯一定下结果的一律直接改，不找用户确认，执行者自己读 override 与 `npc_heroes_custom.txt`、按 P1–P3 定改法。用户在场并明确要求逐条核对时，才改为先出核对表、按 `references/ask-user.md` 询问后再改。

每批走一遍：

1. **核对**：对比上一版与新版 `docs/reference` 目录，得出每条日志的系统名、KV 键、新旧值，以及新旧 diff 里日志没提到的改动
2. **逐技能定改法**，按本图现状：
   - 本图没写该键 → 自动生效（基础属性同理：英雄不在 `npc_heroes_custom.txt` 或没写该字段即继承）
   - override 写了该键 → 按 P1–P3 直接写新值
   - 涉及天赋 → 核实天赋 key 仍在该英雄 `Ability10+` 槽位
3. **命中「待确认」就整个技能不改**（见下）。其余技能与该英雄的 `Bot.Build` 照常改
4. 改完 `git diff` 确认只动了本批英雄的技能块，**每批单独 commit**，最后走「执行顺序」第 4 步校验 `Bot.Build`

多批并行时每批互不等待。开工前与读 override 前确认分支基于最新 `develop`（`git fetch` 后比对），避免与刚合并的同类同步 PR 重复改动。

**以新版参考快照为准**：快照是游戏实际读取的数据，补丁日志与快照不一致时（数值对不上，或日志里有、快照里没有对应键）一律按快照改，不停下，在「自动判定」里记一行差异。按键逐个判定：日志与快照不符本身不触发待确认，也不覆盖同技能其它键命中待确认时的整技能冻结。同一份快照里不同技能的抓取时间点可能不一致，快照仍等于日志「旧值」的技能，按快照的现值处理（即不改）。

### 自动判定与待确认

命中下面任一情形时，**先判断规则能不能唯一定下结果**：能就由执行者直接定下并改好，列入 PR 的 `## 自动判定`，不问用户；定不下来、属于真正的设计取舍，才进「待确认」。

#### 自动判定（直接改，不问用户）

- `xN` / `+N` / `差值N` 规则标记的键：用新基数照规则重算并写入，即使本图实际值变化超过 50% 或与官方改动方向相反也照写（`+N` 碰上官方大砍基数时会大幅变动，这是规则的结果，不是问题）
- 纯等级延伸：用新值重新延伸，补 `延伸` 标记
- 手动值：保留 value，只把注释基数更新为新官方值，前提是本图值仍与新官方值同向且更强（或更弱）。方向翻转或追平的，按「按注释类型重算」里的手动值规则删覆盖
- 补标记：参考里从未有过的键，明显是有意加的（觉醒 `*_upgrade` 天赋键、带中文设计说明注释的键），补 `// 原版不存在，手动修改`
- 官方新版给倍率键新增了天赋 / 子键：本图没写时，按同一倍率换算后写入（`special_bonus_*` 键的数值按该键的倍率；写不出整数时按「倍率出小数」处理：取与原倍率最近的整倍率，距离相等取较大者；仍定不下来走待确认第 2 条）
- 官方改写键名或结构：按 P1「原版结构变化导致的失效键」直接迁移

#### 待确认（命中即停，整个技能不改）

只留真正的设计取舍，规则推不出唯一答案的：

1. **结构变化**：官方把技能的机制拆开、合并或换成别的机制，上面「结构迁移」规则覆盖不了
2. **删除或改变倍率**：照规则重算会让倍率变成另一个数（如 `x2.5` 的结果出现小数又没有相邻整倍率可选），或本图值已无法用任何倍率还原
3. **行为变化**：官方改了技能行为（目标类型、触发条件、新增或移除效果），本图覆盖项的前提可能失效
4. **无法还原规则的值**：注释基数既不等于上一版也不等于新版参考值，且带的规则标记（`xN` `+N` `差值N`）也不能唯一重算出结果（标记能唯一重算的按自动判定直接重算）；或无注释的键，本图值既不是上一版参考值，也不是它按差值延伸的结果（按上一版参考判断，不按新版：拿新版比，官方一改数值，所有无注释的键都会显得「与参考不符」，有意加强就会被冲掉）；或只有中文设计说明、无法判断官方改动对设计意图的影响
5. **官方已实现本图自加内容的同样功能**（如本图自加的天赋、键，或 `npc_heroes_custom.txt` 里替换天赋槽位的自加天赋）：整项列入，建议删除
6. **自加键没有标记，又看不出是有意的**：不属于上面「补标记」两类

**每条待确认必须带建议**：写清当前值、官方新值、你推荐怎么改、为什么停下。

规则：

- **最小单位是技能**：一个技能里只要有一个键命中待确认，整个技能块本批保持原样，不允许改一半留一半
- **顺带发现的旧偏差**（官方本批没动、override 与参考不符）：不改，只在 PR 里列出，不挡合并
- **记录格式**：
  - PR 正文用 `## 自动判定`，每个技能一行：``- **英雄中文名** · 技能中文名 `ability_name` — 改了什么（旧值 → 新值），依据哪条规则``
  - PR 正文用 `## 待确认`，每个存疑技能一行：``- [ ] **英雄中文名** · 技能中文名 `ability_name` — 第 N 条：当前值 → 官方新值，为什么停下。建议：…``
  - 有对应 issue 时，issue 正文用 `### 待确认技能`（没有就新建），格式相同，行尾加 ` · #PR号`。该英雄在 issue 清单里不打勾，直到它的待确认技能处理完
  - 旧偏差另起 `## 顺带发现（未改）`，格式相同但不用勾选框

## 核心规则（按优先级）

维护任一技能时严格按 P1 → P2 → P3 顺序处理，后步不得推翻前步结论。

### P1 删除同值与禁止项

与参考**逐字相同**的键一律不写入 override，已写入的删除。

**同值的定义**（全文只此一处）：

- 单值相同
- 多档每档与参考对应档相同，包括为凑 MaxLevel 而重复末档（参考 `20 20 20`，本图写 `20 20 20 20` 仍属同值）
- 「前几档与参考相同、新档按差值延伸」**不是同值**：参考 `140 150 160 170`，本图 MaxLevel=5 写 `140 150 160 170 180`，第 5 档 ≠ 参考末档，必须写入

**适用范围**：`AbilityBehavior`、`SpellImmunityType`、`AbilityCastPoint` 等属性键，`special_bonus_unique_*` / `special_bonus_scepter` / `special_bonus_shard`，以及子块内任意键（与参考相同就删该行，保留有差分的兄弟键，子块全无差分则删整块）。

**绝对禁止项**：

- `CalculateSpellDamageTooltip`（交给原版）
- `special_bonus_facet_*`（7.41+ 废弃）。若子键仅有已废 facet 而无 `value`，不得新造 `value`
- 参考**曾经存在、现已删除**的键：从 override 删除

**参考从未有过的键（本图自定义）**：

- 行尾注释**明确写有** `// 原版不存在，手动修改` → 保留
- 没有该注释（如仅写 `// x2.5` 或无注释），例如 `LinkedAbility` / `AbilityDraftPreAbility` / 参考中不存在的 `special_bonus_*` → 先看是否属于「补标记」两类（觉醒 `*_upgrade` 天赋键、带中文设计说明注释的键）：是就补 `// 原版不存在，手动修改` 并列入自动判定，否则待确认第 6 条，技能保持原样。用户在场时可按 `references/ask-user.md` 问是否有意添加
- 原版结构变化导致的失效键，**直接处理不询问**：
  - 旧格式 `value "X"`，新格式改成 `special_bonus_scepter "Y"`（或 `special_bonus_shard`）：把旧 `value` 的设计值迁移到新键名，按原注释推断倍率/差值重算，写 `"special_bonus_scepter" "迁移值" // 官方值 [规则标记]`。规则不明确时属待确认第 2 条（无法还原倍率）
  - 旧格式的 `RequiresScepter "1"` 等辅助键在新格式里没有 → 删除
  - 子键在参考中已完全消失（非结构迁移）→ 删除
- 键名改变（旧版 `foo_tooltip` → 新版 `foo`）：删旧键名，按新键名走正常 P1–P3

**天赋**：

- 改动任何天赋前，先在参考 `heroes/npc_dota_hero_<hero>.txt`（7.41f 之前的版本在 `npc_heroes.txt`）该英雄的 `Ability10-17` 核实 key 仍存在：版本更新可能把天赋整体换成另一个 key 甚至另一种机制，只做数值重算发现不了。key 已不存在视为被替换，按新 key 重新处理
- 数值内嵌在天赋名里的通用天赋（如 `special_bonus_cast_range_125`、`special_bonus_attack_damage_15`）是引擎原生实现，只需在 `Ability10-17` / `Bot.Build` 正确引用，不要新增 `AbilityValues` 块

### P2 差分与 MaxLevel 扩展

#### MaxLevel 扩展必扫（强制）

本图 MaxLevel 高于参考时，**以参考该技能整段为全集**扫描所有多档键，禁止只扫 override 已有行：

| 多档键位置 | 说明 |
|-----------|------|
| 块顶多档 | `AbilityCooldown`、`AbilityManaCost`、`AbilityDuration`、`AbilityCastRange` 等 |
| AbilityValues 子块 | `"键" { "value" "a b c" ... }` |
| AbilityValues 顶层平铺（易漏） | 直接 `"键名" "a b c"` 无子块 |

**顶层 vs 子块冲突**：参考把某键（如 `AbilityCooldown`）放在 `AbilityValues` 子块内，而 override 写成顶层时，顶层写法**无效**。直接删 override 的顶层写法，在子块内按 P1–P3 处理。

对参考全集中每个多档键（含「参考有 override 无」的差集）依次判定：

1. 同值（定义见 P1）→ 不写
2. 恒定单值（本图各级同数）→ **单 token**，禁止 `n n n`
3. 随等级变化 → 档数 = 有效 MaxLevel，新档按相邻差延伸

#### 按注释类型重算

处理已有 override 的技能时，**在 P1 删除之前**先逐一核对行尾注释里的参考基数是否等于当前参考值。**基数 = 当前官方值**说明官方没改，不重算，继续 P1–P3 的其余检查（同值删除、扩档、补 `延伸`）。基数不等时按下表处理，都**无需询问**：

| 现有注释 | 处理 |
|---|---|
| `延伸`，或无注释且 value 是参考值按差值的延伸 | 用当前参考值重新延伸，补 `延伸` 标记 |
| 无注释，value 不是当前参考的延伸 | 和上一版参考比：是上一版值或其延伸 → 同步官方最新值并补全新档、补 `延伸`。官方把多档改成不分档单值时，上一版的延伸值就是新单值，按 P1 删整个键。不是 → 待确认第 4 条 |
| 规则标记 `xN` `+N` `差值N`（有无基数都算） | 用当前参考值按规则重算并写入，补全基数。重算结果与现有 value 不符、也没有旧版参考可对照时同样直接重算。注释同时有中文说明（如 `// 15 30 x2 加强`）时规则标记优先 |
| 只写参考值、没有规则标记（如 `"25" // 20`） | value 是参考值的延伸 → 按第一行。是固定倍数（`30 40 50 60` 对 `15 20 25 30`）→ 按规则标记行，补 `xN`。都不是 → 本图手动值，见下 |
| 只有中文设计说明 | 官方改了该值 → 按「手动值」处理：本图值仍同向更强就只更新注释基数，方向翻转或追平就删覆盖，都列入自动判定；看不出设计意图受什么影响才是待确认第 4 条 |

**手动值**：保留 value，只把注释里的参考值更新为当前官方值。保留前做反超检查：本图值相对旧官方偏强或偏弱，新官方值把方向翻转或追平时，手动值的前提已消失，删除该覆盖键直接继承官方，并在 PR「平衡取舍」节列出原手动值与新官方值。

**倍率出小数**（如 `+15 x1.5` 得 `+22.5`）：不写小数，改用相邻整倍率（`x2`），在 PR「平衡取舍」节列出原倍率与新倍率。

**停下的情形**：注释基数既不是上一版也不是新版参考值、推不出规则 → 待确认第 4 条，技能保持原样。规则标记键重算结果变化再大也照写，不停。

#### 数值计算

| 情形 | value 处理 | 行尾注释 |
|------|-----------|---------|
| 仅等级扩展 | 前几档同参考，新档按差值延伸 | `// 参考各档 延伸` |
| 固定差值 | 每档 = 参考 + N | `// 参考各档 +N` |
| 倍数 | 先推参考第 N 档再乘倍率 | `// 参考各档 xN`（基数**必须**写出） |
| 自定义键（已有 `// 原版不存在，手动修改`） | 保留本图值，同样须做 MaxLevel 扩展 | `// 原版不存在，手动修改` |
| 参考曾有、现已删除 | 删除（P1 禁止项） | — |
| 百分比键（`_pct` 结尾或明确表示百分比） | 各档不超过 100。参考最大值 > 50、延伸会超 100 时改写差值使末档恰好等于参考最大值：差值 = `(max - 首档) / (MaxLevel - 1)`，不能整除就近取整。例：参考 `40 60 80 100`，MaxLevel=5 → `40 55 70 85 100` | `// 参考首档…末档 差值N` |

#### 冷却

目的：最高等级冷却不过短，各档等差、取整好看。本节规则用于冷却的等级扩展，按本节算出的值不写注释。冷却带倍率、固定差值或设计说明时按「按注释类型重算」处理。旧版「档数不足一律取参考末档」与「未触下限直接延伸」相冲突，以本节为准。

- **公差**：有本图公差用本图公差，否则用官方公差（本图无该技能记录时用参考相邻差）
- **下限**：把官方各档按公差延伸到 MaxLevel。延伸出的末档低于下限（小招 10 秒 / 大招 60 秒）时，末档改取官方末档，从末档向前按公差递推。没低于下限就直接延伸
- **等差优先**：递推结果各档都比官方对应档长也照用，不为贴近官方把末几档写成相同值（参考 `14 12 10 8`，MaxLevel=5，写 `16 14 12 10 8`，不写 `14 12 10 8 8`）
- **取整**：尽量取 5 或 10 的整数倍，保持等差。递推后首档与参考首档偏差达到 20% 及以上，或本图原有首档更接近参考首档时，可改用另一个整数公差让首档更接近，末档不变（参考 `15 12 9 6`，MaxLevel=5，本图原有 `14 12 10 8 6` 保留）

示例：

| 参考 | 公差 | MaxLevel | 结果 | 说明 |
|---|---|---|---|---|
| `55 35 15`（大招） | 本图 -10 | 4 | `45 35 25 15` | 延伸末档 5 低于 60，末档取 15 |
| `22 18 14 10` | 官方 -4 | 5 | `26 22 18 14 10` | 延伸末档 6 低于 10，末档取 10 |
| `12 10 8 6` | 官方 -2 | 5 | `14 12 10 8 6` | 首档偏差 16.7%，不微调 |
| `100 90 80`（大招） | 官方 -10 | 4 | `100 90 80 70` | 70 不低于 60，直接延伸 |

### P3 注释格式

仅在 override 值与参考不同时写行尾注释。格式：`"本图值" // 参考值 [规则标记]`

| 场景 | 示例 |
|------|------|
| 单值对照 | `"12" // 18` |
| 多档对照 | `"90 80 70 60" // 150 130 110` |
| 纯等级扩展 | `"21 20 19 18 17" // 21 20 19 18 延伸` |
| 倍数 | `"30 60 90 120 150" // 15 30 45 60 x2` |
| 固定差值 | `"300 500 700 900" // 200 400 600 800 +100` |
| 改差值 | `"3 3.5 4 4.5 5" // 3 4 5 6 差值0.5` |
| 参考值 + 设计说明 | `"=0" // =1 移除 连环霜冻无限弹跳天赋` |
| 纯设计说明 | `// 原版不存在，手动修改`、`// 百分比伤害，限制上限` |

- 顺序：`//` 后先写当前参考官方数，再写规则标记，中文设计说明放最后（如 `// 15 30 x2 加强`）。已有的说明保留
- 倍数标记**必须**同时写参考数，禁止 `// x2` 无基数
- 同值不占坑（`"30" // 30` → 删整行）
- 本图值是官方值的延伸时必须带 `延伸` 标记，原来没写的改到时补上，不全量补。只写参考值不带标记表示手动值，两者不能混用
- **禁止**：分号分隔、命石/facet 名称
- 增加参考不存在的键 → 行尾 `// 中文原因`
- 沿用同文件、同英雄区段已有注释风格

## 执行顺序（逐英雄）

1. **定范围**：从参考英雄文件（+ `npc_heroes_custom.txt`）确定技能列表
2. **逐技能**：
   a. 读参考整段，列出全部多档键（全集）
   b. 读 override 该技能块，标出差集（参考有 override 无）
   c. 已有 override 的：先核对注释基数（「按注释类型重算」），再 **P1** 删同值键 + 禁止项
   d. **P2**：处理差分、扩展新档、重算倍数/差值
   e. **P3**：校验注释格式
3. **自检**：
   - [ ] 无同值抄写、无全相同 token 多档行、恒定值用单 token
   - [ ] 无 `special_bonus_facet_*`、无 `CalculateSpellDamageTooltip`
   - [ ] 无参考中已不存在的键（含改名键如旧 `foo_tooltip` → 新 `foo`）
   - [ ] MaxLevel 扩展已扫参考全文含差集（块顶 + 子块 + 顶层平铺）
   - [ ] 百分比键各档不超过 100，延伸会超过 100 时已改写差值封顶
   - [ ] 有注释的键：参考基数与当前版本一致，规则标记与 value 重算结果一致
   - [ ] `延伸` 标记与无注释的键（冷却按「冷却」小节，不在此列）：value 与参考差值延伸完全吻合，本次改到的纯延伸行都带 `延伸`
4. 所有英雄处理完毕后，调用 `update-bot-hero-build` 对本次修改的英雄逐一验证 Bot.Build 合规性（英雄不在 `npc_heroes_custom.txt` 时无 Bot.Build，跳过）
