# 本地主机策略

> 背景：Dota 2 官方自定义游戏服务器故障，玩家在可预见的一段时间内只能用本地主机开局。本文档给出「哪些功能在本地主机直接放开、哪些必须走网站登录」的总体建议，不展开技术实现细节。

## 一句话结论

**本地主机只做「读取、限额产出、个人设置、小额会员积分消耗、自己掏钱的充值」；所有改变账号养成状态的操作（加点、洗点、觉醒）一律改到网站（Steam 登录）操作，游戏内只做跳转和刷新。**

## 1. 问题是什么

官方服务器与本地主机能够支持的账号功能不同。客户端目前会提前拦截大部分 API，因此设置保存、排行榜、付费刷新等适合本地主机的功能也无法使用；加点、洗点和觉醒等账号养成功能则需要迁移到网站。

本策略按功能影响分档：读取和个人设置可以直接使用，少量资源产出或消费需要限额，永久改变账号养成状态的操作统一通过 Steam 登录网站完成。

### 当前代码现状

客户端侧 `ApiClient` 在本地主机只放行三个路径，其余请求直接在本地返回 401，根本不会发到后端：

| 接口 | 用途 | 本地现状 |
|------|------|---------|
| `GET /game/start` | 加载玩家数据、每日任务候选 | 放行 |
| `POST /game/end/local` | 本地结算（后端限每日 2000 勇士积分） | 放行 |
| `POST /daily-task/refresh` | 刷新每日任务候选 | 放行 |
| `PUT /player/:id/property` | 勇士积分加属性点 | 拦截 |
| `DELETE /player/:id/property` | 洗点（勇士积分 / 会员积分） | 拦截 |
| `PUT /player/:id/setting` `game-preset` | 键位、预设保存 | 拦截 |
| `GET /player/:id/info` | 刷新玩家信息（会员状态） | 拦截 |
| `GET /player/ranking` | 排行榜 | 拦截 |
| `POST /player/member-points/use` | 抽奖付费刷新（会员积分） | 拦截（抽奖模块另有本地判定） |
| `PUT /player/:id/hero-awakening` `/random` | 觉醒解锁、随机觉醒 | 拦截 |
| `POST /player/conduct` | 点赞 / 举报 | 拦截 |
| `POST /alipay/order/*` | 支付宝购买会员 | 拦截 |

前端目前没有「当前是本地主机」的标记，按钮点了没反应，玩家只能靠加载页 FAQ 得知原因。

## 2. 分级原则

判断功能放在哪一档，依次看三个方面：

1. **是否只读取数据或保存个人设置？** 是 → 本地主机直接使用。
2. **是否产生或消耗积分？** 是 → 仅开放适合局内使用的小额操作，并设置限额。
3. **是否永久改变账号养成状态？** 是 → 通过 Steam 登录网站操作。

| 档位 | 定义 | 处理方式 |
|------|------|---------|
| A 本地直接放开 | 只读、个人设置或购买会员 | 后端允许，并做必要校验 |
| B 本地放开但限额 | 少量产出或消费资源 | 后端按账号设置限额 |
| C 仅网站 | 永久改变账号养成状态 | 网站登录后操作，游戏内提供状态展示 |

## 3. 功能分档建议

### 总览表

| 功能 | 当前（本地主机） | 未来打算 | 本地主机是否允许 | 不允许时是否迁移到网站 |
|------|-----------------|---------|-----------------|---------------------|
| 加载玩家数据、每日任务候选 | 允许 | 不变 | 允许 | — |
| 本地结算勇士积分 | 允许，每日 2000 上限 | 暂时保持 2000，后续看情况上调 | 允许（限额） | — |
| 每日任务（领取、刷新候选、结算奖励） | 允许 | 不变 | 允许 | — |
| 会员签到 | 允许 | 不变 | 允许 | — |
| 键位、游戏预设保存 | 拦截 | 后端允许 | **改为允许** | — |
| 玩家信息刷新（会员状态、属性） | 拦截 | 后端允许，兼作网站操作后的同步入口 | **改为允许** | — |
| 排行榜读取 | 拦截 | 后端允许 | **改为允许** | — |
| 购买 / 续费会员（支付宝） | 拦截 | 后端允许 | **改为允许** | —（网站也提供购买入口，两边都能买） |
| 抽奖付费刷新（会员积分） | 拦截 | 放开，后端限每日 1000 会员积分、单笔不超过 50 | **改为允许（限额）** | — |
| 勇士积分加属性点 | 拦截 | 游戏内属性面板改为只读 + 「前往网站」 | 不允许 | 迁移到网站 |
| 洗点（勇士积分 / 会员积分） | 拦截 | 同上 | 不允许 | 迁移到网站 |
| 觉醒英雄解锁（直购 / 半价认领） | 拦截 | 游戏内按钮改为「前往网站」 | 不允许 | 迁移到网站 |
| 随机觉醒抽候选 | 拦截 | 同上，候选集在网站生成与认领 | 不允许 | 迁移到网站 |
| 点赞 / 举报 | 拦截 | 后端继续拒绝 | 不允许 | 不迁移（网站无对局上下文） |
| GA4 统计上报 | 不上报 | 本地主机也下发统计配置 | **改为允许** | — |

以下按档位说明理由。

### A 档：本地直接放开

| 功能 | 理由 |
|------|------|
| 加载玩家数据、每日任务候选 | 已支持 |
| 键位、游戏预设保存 | 个人设置 |
| 玩家信息刷新 | 只读，同时用于同步网站操作后的结果 |
| 排行榜读取 | 只读 |
| 每日任务候选刷新 | 已支持，次数由后端控制 |
| GA4 统计上报 | 保留本地主机对局统计 |
| 购买 / 续费会员（支付宝） | 游戏内和网站均提供购买入口 |

### B 档：本地放开但限额

| 功能 | 限额 |
|------|------|
| 本地结算勇士积分 | 每日 2000 上限，后续按运营情况决定是否调整 |
| 每日任务奖励 | 奖励固定且每日一次 |
| 会员签到 | 每日一次 |
| 抽奖付费刷新（会员积分） | 每日 1000 会员积分，单笔不超过 50 |

### C 档：仅网站操作

| 功能 | 理由 |
|------|------|
| 勇士积分加属性点 | 永久改变账号属性分配 |
| 洗点（无论使用勇士积分还是会员积分） | 重置账号养成状态并消耗积分 |
| 觉醒英雄解锁、随机觉醒 | 账号级永久解锁与消费 |
| 点赞 / 举报 | 依赖对局上下文，本地主机下不提供 |

## 4. 网站方案

使用 Steam 登录的网站承载 C 档账号操作，游戏内继续负责展示状态、跳转和刷新。

### 网站需要提供的页面

- 属性面板：查看当前属性，加点，洗点
- 觉醒：查看已觉醒英雄，解锁、随机
- 会员：查看积分与到期时间，购买 / 续费（游戏内也能买，网站是第二入口）
- 记录：查看最近的积分变动和消费记录

### 游戏内配合

- 加载完成后向客户端下发「当前是否本地主机」，前端据此把 C 档按钮显示为「前往网站操作」，属性面板在本地模式下只展示、不能点
- 各页面保留「刷新」按钮，玩家在网站操作完后回游戏手动刷新，不做即时推送。这一步放在最后实现
- 加载页 FAQ 说明本地主机可以使用的功能，以及需要前往网站的功能

### 后端配合

- 按运行环境统一管理接口权限，客户端不维护重复的权限名单
- 对本地主机开放的积分和支付操作实施必要校验与限额
- 账号养成操作只通过网站登录入口执行

## 5. 分阶段落地

| 阶段 | 内容 | 目的 |
|------|------|------|
| 1 立即 | 客户端移除本地主机 API 路径限制和抽奖付费刷新拦截；后端统一接口权限并限制会员积分消费；游戏内加本地主机标记，加点等 C 档按钮置灰，鼠标悬停提示「新的加点方式开发中」 | 让后端统一裁定权限，同时让玩家知道加点为什么不能用 |
| 2 短期 | 网站 Steam 登录 + 属性 / 觉醒 / 会员页面；游戏内跳转按钮；FAQ 文案更新 | 补上加点、洗点、觉醒 |
| 3 收尾 | 游戏内「刷新」按钮同步网站操作结果 | 网站与游戏数据打通 |
| 4 视情况 | 结算上限调整 | 调整本地主机养成节奏 |
| 5 官方恢复后 | 保留网站作为长期入口，本地策略继续生效 | 官方服务器再挂时不用重来一遍 |

### 阶段 1 细分

game（Workshop 地图）和 firebase（后端）是两个独立发布的东西，阶段 1 拆成两步：**后端先上，game 后上**。后端只是多放行几个接口，旧地图在本地根本不会调它们，先上没有副作用；反过来新地图先上，玩家会对着还没放行的接口撞 401。

**1a 后端（可以按接口拆成多次部署，不必一次上完）**

| 改动 | 说明 |
|------|------|
| 本地主机接口权限 | 允许键位 / 预设保存、玩家信息刷新、排行榜、会员积分消耗、支付宝下单与查询 |
| 会员积分消耗限额 | 每个账号每日 1000、单笔 50，超出直接拒绝 |
| 支付宝下单 | 支持本地主机发起与查询订单 |
| 开局接口 | 本地主机也返回 GA4 配置 |


**1b game（一次 release）**

| 改动 | 说明 |
|------|------|
| 客户端 API 限制 | 删除路径名单和发送前拦截，所有接口权限由后端统一裁定 |
| 抽奖付费刷新 | 去掉技能 / 物品抽奖里的本地主机拦截，限额交给后端 |
| 本地主机标记 | 开局后把「是否本地主机」下发到客户端，供前端判断 |
| 加点 / 洗点 / 觉醒按钮 | 本地主机下置灰，悬停提示「新的加点方式开发中」 |
| 加载页 FAQ | 改写本地主机条目，说明现在哪些能用 |
| 本地化文案 | 上面两项涉及的中英俄文案 |

game 侧这几项都很小，合成一次 release 即可，不建议再拆。若置灰 UI 拖了进度，可以先发移除客户端拦截的部分，让玩家先把设置保存、排行榜、付费刷新用起来，UI 随下一次 release 补上。

## 6. 已定决策

- 抽奖付费刷新：每日会员积分消耗上限 1000，单笔不超过 50
- 网站操作后的同步：玩家手动点刷新，不做即时推送，最后实现
- 点赞 / 举报：本地主机仍不允许，客户端不单独维护权限名单，由后端拒绝
- 网站上线前：本地主机下加点按钮置灰，鼠标悬停提示「新的加点方式开发中」
- GA4 统计：本地主机也上报
