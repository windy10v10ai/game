# 本地主机策略阶段 1：game 侧设计

> 对应 game issue #2407。前置条件是后端 windy10v10ai/firebase#1105 已部署，避免新地图在本地主机请求尚未放行的接口。

## 背景与目标

客户端目前只允许本地主机访问开局、结算和每日任务刷新三个固定路径，其余请求在发送前直接返回 401。与此同时，技能和物品抽奖仍单独阻止本地主机付费刷新，前端也不知道当前是否为本地主机，因此加点、洗点和觉醒按钮点击后没有明确反馈。

本阶段在一次 game release 中完成以下工作：

- 删除客户端的本地主机 API 路径限制，由后端统一决定接口权限
- 恢复技能与物品抽奖的付费刷新，由后端统一限制消费额度
- 向 Panorama 下发本地主机标记
- 在本地主机下禁用加点、洗点和觉醒操作，并显示统一提示
- 简要更新加载页 FAQ

点赞和举报在本地主机下仍不允许，但改由后端拒绝；结算、每日任务和会员签到保持现状。网站入口和网站操作后的数据刷新不在本阶段实现。

## 设计决策

### API 权限边界

删除 API 客户端内的本地主机路径名单和发送前拦截。无论运行在官方服务器还是本地主机，游戏端都把实际发生的请求发给后端，由后端根据请求来源和接口策略决定是否允许。

客户端和后端各自维护权限名单容易失去同步，因此接口权限统一由后端管理。设置、预设、玩家信息、排行榜、会员积分消费和支付宝订单允许本地主机使用，属性、觉醒、点赞和举报继续拒绝。

现有调用中没有必须禁止的周期请求。加点、洗点和觉醒在本地主机下会由 UI 禁用；点赞和举报只有玩家主动点击时才会产生一条被拒绝的请求，不会形成持续流量。

### 抽奖付费刷新

移除技能抽奖和物品抽奖各自的本地主机拦截。会员资格、游戏内刷新次数和可用积分判断保持不变，会员积分消费请求直接发送给后端。

每日 1000 会员积分、单笔不超过 50 的消费限制由后端负责。游戏端不重复实现该限额，避免两端规则逐渐不一致。现有乐观更新流程保持不变，后端回包继续作为会员积分的最终数据来源。

### 本地主机标记

新增 `server_env` net table，使用同名固定行保存 `is_local_host`。字段以 `0` 或 `1` 表示，符合 Panorama 接收布尔值的项目约定。

VScripts 初始化模块时通过现有的运行环境判据计算并写入一次。该值在一局内不会改变，不需要后续事件或定时同步。

现有 GA4 `SERVER_TYPE` 不作为 UI 判据。它来自开局接口返回的统计配置，只供 GA4 内部使用，而且是否存在取决于后端响应；UI 标记应由游戏服务器环境直接决定。

新增 net table 时同步更新类型声明与引擎注册文件。由于引擎不会在 `script_reload` 时重读 net table 注册文件，实机验证前必须重启 Dota Tools。

### 加点、洗点和觉醒按钮

属性操作仍位于传统 Panorama 的 `battlepass.js`，觉醒操作位于 React `hud_main`，两套 UI 都读取同一个 `server_env` 标记。

传统 Panorama 在本地主机下禁用：

- 每项属性的升级按钮
- 支持该操作时显示的一键满级按钮
- 勇士积分洗点按钮
- 会员积分洗点按钮

React 觉醒页在本地主机下禁用：

- 随机觉醒按钮
- 所有未解锁英雄的直购按钮

所有上述按钮共用一个本地化提示，方向为“本地主机暂不支持该功能，新的操作方式开发中”。本地主机限制优先于积分不足、候选池不足等普通禁用原因，避免向玩家显示无法解决的次要原因。

官方服务器不受该标记影响，继续使用现有资格、积分和候选池判断。

### 加载页 FAQ

`loading_faq_local_host_answer` 只做方向性说明，不逐项解释内部策略或接口：

- 本地主机可以正常游戏
- 设置、键位、排行榜和抽奖付费刷新可以使用
- 本地结算仍有每日上限
- 加点、洗点和觉醒暂不支持，新的操作方式正在开发

FAQ 和按钮提示同时维护简体中文、英文、俄文，三种语言表达一致。

## 数据流

### 环境标记

1. VScripts 初始化模块。
2. 游戏端通过现有运行环境判据判断是否为本地主机。
3. 判断结果写入 `server_env` 的固定行。
4. 传统 Panorama 直接读取该行，控制属性与洗点按钮。
5. React 页面通过现有 net table hook 订阅该行，控制觉醒按钮。

### 本地 API 请求

1. 调用方提交请求。
2. API 客户端按现有认证方式发送请求。
3. 后端根据请求来源和接口策略决定允许或拒绝。
4. 后端负责接口权限、会员积分限额和支付请求校验。
5. 游戏端按现有成功或失败回包流程更新状态。

## 异常与边界处理

- 本地主机标记尚未读取到时，前端按非本地主机处理，避免 net table 初始化顺序短暂影响官方服务器操作；数据到达后立即按真实值更新。
- 付费刷新接口被后端拒绝时，沿用现有失败回包和玩家信息同步机制，不在本阶段新增提示流程。
- 本地主机下按钮禁用只负责前端反馈，属性、觉醒、点赞和举报接口仍由后端拒绝。

## 验证方式

### 自动验证

- 运行现有抽奖测试，确认付费刷新规则未被破坏
- 运行 lint、VScripts 构建和 Panorama 构建

### Dota Tools 实机验证

重启 Dota Tools 后分别验证本地主机与官方服务器：

- 本地主机标记能够下发并被两套 UI 读取
- 加点、一键满级、洗点、随机觉醒和直购觉醒均置灰，悬停提示一致
- 设置、键位和游戏预设能够保存
- 玩家信息和排行榜能够读取
- 技能与物品抽奖的付费刷新能够成功，积分结果以后端为准
- 点赞和举报请求由后端拒绝，且不会改变玩家数据
- FAQ 显示新的简短说明
- 官方服务器上的全部按钮和请求行为保持不变
