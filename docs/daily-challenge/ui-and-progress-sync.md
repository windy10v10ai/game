# 每日挑战 UI 与进度同步

## 1. PC 页面布局

每日挑战使用接近会员页面的宽屏模态布局，可占屏幕约三分之二。顶部显示标题、挑战日和赛季积分，页签包含：今日挑战、连续挑战、奖励记录、规则。

“今日个人挑战”区域必须优先展示：

- `第 X/3 轮 · 已完成 Y/3`；
- 当前任务星级和实际赛季积分奖励；
- 待选、进行中或三轮完成状态；
- 未接取时的全天刷新额度。

入口可使用红点或未读数字。未读数量来自快照 `unreadRewardCount`，进入页面后通过查看事件清除，不能在本地直接假设已读。

## 2. 待选状态

每轮横向展示三张卡：两张通用任务、一张英雄专属任务。每张卡显示：

1. 星级视觉标签；
2. 玩家可读标题和说明；
3. 目标量；
4. 快照实际奖励；
5. 接取按钮。

三个候选允许同星。刷新按钮与次数显示在个人挑战标题区域，次数按全天共享。

## 3. 已接取状态

接取后继续显示本轮和星级，并展示：

- 正式累计进度；
- 当前局暂存进度；
- 进度条；
- 手动同步按钮；
- 距离下一次 5 分钟自动同步的倒计时；
- 正常结算后才计入正式进度的提示。

手动/自动同步不代表奖励已发放；最终以正常赛后快照为准。异常结算时后端和游戏端不得把当前局暂存值写入正式进度。

## 4. 完成与下一轮

完成第 1 或第 2 轮后，后端在赛后动作结果或后续快照中返回下一轮候选。React state 更新后自动显示新的三张卡，不额外弹出空状态。

完成第 3 轮后显示：

- “今日个人挑战已完成”；
- 三轮完成任务列表；
- 每轮星级与奖励；
- 当天个人任务奖励总计。

此时不显示刷新按钮，也不显示“暂无任务”。

## 5. 规则文案

规则页固定说明六点：每天三轮、每轮三选一；随机星级允许同星；星级目标与奖励不同；正常结算后即时发奖并进入下一轮；比赛归属/10 分钟接取/5 分钟同步；全天刷新额度、共同任务次日发奖、连续完成要求三轮全完成。

任务文案必须使用玩家语言和单位，如“300 秒”“造成 50 万点魔法伤害”，不得展示 `target`、`metric`、“目标秒”等实现字段。

## 6. 三语一致性

简中、英语和俄语的全部 `daily_challenge_*` key 必须一致；占位符必须保持一致。重点占位符包括：

- `{current}`、`{completed}`、`{total}`；
- `{star}`、`{points}`、`{count}`；
- `{free}`、`{remaining}`；
- `{n}`、`{time}`、`{day}`。

任何新增玩家可见文本都必须先补齐三语再通过构建。
