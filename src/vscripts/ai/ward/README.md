# bot 插眼

假眼 = 侦查守卫（`item_ward_observer`，配置里 `OBSERVER_*`），真眼 = 岗哨守卫（`item_ward_sentry`，`SENTRY_*`）。

## 结构

| 文件 | 内容 |
|---|---|
| `ward-position-config.ts` | 眼位数据与可调参数。天辉、夜魇各一份，真眼假眼各一份，按「组 → 区 → 备选点」组织，运行时 `getWardZones` 才转成 `Vector` |
| `ward-decision.ts` | 不查引擎的判定：区是否空闲、档位是否启用、给每个组抽当前目标区（`resolveTargets`）、取最近目标、反隐触发、谁来买眼 |
| `ward-placement.ts` | 采集引擎数据并施法：本队各组的当前目标 `TargetsOf`，路过插眼 `Run`，被隐身敌人打到时的真眼 `OnDamaged` |
| `ward-supply.ts` | 团队补眼：假眼全队上限 4，真眼全队上限 3、每人最多 1 个，都给玩家留 2 个库存。持有数阵亡电脑身上的也算。一个电脑只带一种眼：身上有另一种眼的不当买家（两种眼会并成一格组合守卫，脚本施放插出的只会是假眼，反隐插不出真眼）。组合守卫整件按假眼算，其中的真眼不计入真眼持有数，也不会被反隐查找用到。买家只挑活着、确认是电脑、有格子且离空区域不远的人 |
| `../hero/roadside.ts` | 顺路办事里的「带假眼去最近的当前目标点插眼」 |

## 决定

- **点位按阵营分开**：电脑只用本方那份。眼位表来自逐点用真实物品插下验证的结果，坐标照搬，附近位置有游戏禁插区，不要手改
- **三层结构：组 → 区 → 备选点**：
  - 组是同一条路线上互相替代的几个区（如「下河道视野线」），每组有上限 `groupLimits`，同时最多这么多只本方同种眼
  - 区是一个路口、一段河道、一个野区入口，2 个备选点，同一区同时最多一只眼。区内任一备选点 900 内已有己方同种眼就算占用（玩家插的也算），所以不同区的点要隔开 950（去重半径加落点偏移），测试里查
  - 备选点：抽到区后在 2 个点里等概率取一个，落点再在 50 范围内抖动，所以每局眼位不同
  - 真眼、假眼各自独立的组与计数，同坐标不合并
- **分档开关**：区的 `tier` 决定何时启用。`always` 与 `attack` 随时。`defend` 绑定己方塔，己方塔倒后才启用，用来守己方野区与高地。`push` 绑定敌方塔，敌方塔倒后才启用。判定是 `isZoneEnabled`，用 `CachedTowers()` 的存活塔名，塔单位名里含 `tower` 字段的片段就算活着。塔缓存为空（还没就绪）、或区缺 `tower` 字段时一律不启用，只有缓存非空且确认绑定塔已不在才启用
- **组内随机抽目标，不按离英雄远近挑**：近的眼位总被插、偏的永远没人去，就是按距离挑的后果。做法是队伍级别为每个有空槽的组预先抽一个「当前目标」（`resolveTargets`）：
  - 组已用数按眼实体算：落在该组任一区 900 内的不同己方同种眼各计一次（一只眼跨两个区只占一个名额，一区两只眼占两个），再加上未落地的认领。认领旁已有真眼时视为同一只落地，不重复计。已用数达到组上限不再抽。区是否空闲仍看任一备选点 900 内有没有同种眼
  - 从组里已启用且未占用的区中等概率抽一个区，再在区内等概率抽备选点
  - 抽定后记住（`TargetPick`），直到插下、区被占用、档位失效，或超过 90 秒（`WARD_TARGET_SECONDS`）仍没插下才重抽
  - 目标列表按队伍与眼种缓存 1 秒，只缓存抽签结果，不当施法许可：路过插眼在下令前、绕路走到施法距离外 300 时（`RoadsideTick`）都会用新数据再查一次（`canPlaceInZone`：区是否已被占、组是否已满、塔状态），不通过就放弃并释放认领
  - 电脑顺路插眼只去这些当前目标点，在顺路范围内取离自己最近的一个（`pickNearestTarget`）。所以组内是随机的，路过的人只负责把已定目标补上
- **覆盖偏远的组**：电脑身上带着假眼超过 45 秒（`WARD_LONG_DETOUR_AFTER`）还没插下，绕路范围从 2500 放宽到 3500（`WARD_LONG_DETOUR_RANGE`）。抽区仍不看距离，只放宽持眼电脑能去的范围，绕路的安全条件（附近没有敌方英雄等）不变。绕路的步行窗口按直线距离乘 1.5 估算、上限 12 秒，窗口太短会被别的命令盖掉施法命令
- **补眼**：本队该眼种还有任一当前目标（有空槽的组）就补，不看买家离目标多远，额度规则不变。真眼不看目标，常规点位只能用到全队真眼额度减 1（`regularCap`），留一只给反隐
- **同一片区域一次只发一条命令**：路过插眼和绕路插眼共用 `WardPlacement.Claim`，记下命令的落点，16 秒（绕路步行上限加施法余量）内当作已有眼参与区去重，绕路被打断或改令时立即释放（`CancelRoadside`），路过插眼与绕路到场前复核失败也会释放（`ClaimedSpots` 并进己方眼列表），所以这个区被占用，组里还有空槽时会抽别的区，与它相距 900 内的相邻区也不会再派人。眼是否真正落地另看区域里有没有己方眼。同一个电脑绕路途中不再发路过插眼
- **备用栏的眼也能买能用**：主物品栏满的电脑也买，插眼前把眼换进主物品栏末位，用完后物品整理把被挤开的物品挪回。只靠主物品栏有空位买眼时，后期几乎所有电脑都满格，补不上
- **不再有脚下随机插眼**：眼只插在预设点位。身上带假眼的电脑，在顺路办事的空闲时机，去 2500 范围内最近的当前目标点插眼，同一区域同一时间只派一个电脑，认领未落地时 16 秒内不再试
- **反隐**：电脑被处于隐身状态的敌方英雄打到，身上有真眼、900 内没有己方真眼（含刚下令未落地的认领），就在脚下插一个，每个电脑 30 秒最多一次。这是明确的例外：紧急情况可以突破组上限与常规真眼额度，下令时留一个认领，所以同一处不会被队友重复下令。受伤事件走 `ModifierEventHub.RegisterDamageByVictim`，在 `BotBaseAIModifier` 里登记。靠攻击瞬间 `IsInvisible()` 判断，影刃这类出手就现身的隐身不会触发，月刃、永久隐身类会触发
- **真眼也有预设点位**：真眼同样分组、分档，由路过插眼的同一套目标逻辑负责，另外靠反隐触发在脚下补
